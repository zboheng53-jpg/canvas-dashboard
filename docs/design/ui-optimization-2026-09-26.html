优先建议 · A 清晰工作台

保留框架，精修主次。

现有界面已经有完整的浅色视觉基础。最值得做的是压缩环境信息、突出任务标题、合并重复元信息，以及让手机首屏真正容纳待办。

A 延续现有风格；B 探索更温和的纸感；C 探索更高的信息密度。三者在下方使用同一组演示事项。

01 / Observe

当前界面，问题在哪里？

以下是当前代码运行出的真实截图，使用隔离示例账户。问题是信息的权重与呈现细节；已有的三栏结构、统一控件和底部导航值得保留。

1440 × 1000 · normal 示例数据。桌面待办卡从 y ≈ 272 px 开始；顶部环境卡与统计卡合计约 218 px（不含间距）。
01 / 视觉权重

环境信息比行动更醒目

天气、秒级时钟和三个统计卡占据中央上方大块空间；任务标题反而较小。统计说明中也有“待完成 4 / 4 项待处理”的重复。

→ 日期、学期、天气压成一条背景信息；待办标题成为首要视觉锚点。统计保留，但改成短摘要。

02 / 行内信息

同一来源，出现两遍

桌面行的标题下方已有“项目 / 自定义”标识，右侧又展示来源；无日期项出现空日期胶囊。小控件和分隔线让阅读节奏零碎。

→ 来源与课程并入一行辅助文字；日期区明确写“截止 / 计划 / 未设日期”。常用完成操作前置。

03 / 右栏层级

主项目还可以更突出

主项目已有蓝色描边，但其他项目也各自占用完整卡片。“下一步”大量重复；右下日程对今天和后续日期的视觉区分偏弱。

→ 保留主项目与当前一步的完整信息；其他项目用短行收纳。日程优先今天，明天以分隔线接续。

04 / 手机首屏

表单挤占了清单

在 390 × 844 视口中，新增表单高约 225 px，第一条任务从 y ≈ 693 px 才开始。页面未横向溢出，但需要滑动才能开始浏览多条待办。

→ 新增变成标题旁按钮，点击再打开表单；保留底部入口，用页内“待办 / 项目 / 日程”减少纵向堆叠。

这些是基于当前示例场景的设计判断，不是用户研究结论。数值来自浏览器元素几何读取；未测试真实平台登录或同步。常规截图的任务与下方原型示例并不相同，下方 A / B / C 之间使用同一数据，以便公平比较。

02 / Explore

三个方向，同一个工作区。

区别不仅是换色：标题风格、导航宽度、任务间距、表面分隔和右栏密度都会变化。A 最接近既有设计约定；B、C 是供选择的探索方案。

A · 清晰工作台

推荐

冷白、墨蓝、细边框。收紧顶部，将注意力留给任务标题和时间；所有区域保持熟悉的位置。

气质

B · 安静书桌

温和阅读

米白、苔绿、编辑式标题。拉开任务间距，用线条组织内容，减少浮在页面上的卡片感。

C · 精密控制台

高密度

石板灰、深色窄导航、紧凑列表。让更多条目进入视野，强调对齐、时间列和信息扫描。

A / 清晰工作台

冷白基底 · 任务标题优先 · 适中密度 · 最接近现有产品

可以试：切换方案与设备、切换场景、按时间筛选、点任务看详情、完成并撤销、添加一条演示待办。边界：仅总览交互原型，全部为合成数据，不接真实 API；左侧导航与底部导航为布局示意。手机上会自动使用窄屏布局。
03 / Refine

比换颜色更重要的细节。

无论选择哪个方向，都建议先落实这些共同改进。保持信息可辨认，同时减少重复、装饰和常驻操作。

一条任务，只讲一遍来源

完成放在左侧，标题形成连续阅读线；来源保留文字，但只出现一次。次要操作放进详情或更多菜单。

04 / Decide

先选视觉方向，再分步落地。

这里不估算虚假的转化率或效率提升。可用“首屏能看到什么”“找到截止时间需要几步”“密集内容是否仍清楚”来判断改动是否有效。

第一步 / 可独立验收

整理列表与手机首屏

合并来源、去掉空日期胶囊、新增表单改为按需打开、明确计划与截止。先在现有风格下改善结构，不依赖整套换肤。

第二步 / 按选定方案

收敛视觉与右栏层级

调整 Token、标题和摘要；主项目突出当前一步，其他项目缩成短行；日程把今天与未来分清。沿用现有语义组件。

第三步 / 最终验收

验证真实数据与异常状态

验证多平台长标题、重复待办、历史计划、空态、同步失败、键盘与手机。先本地验收，再按既有流程发布；方案页不代表生产实现完成。

我的选择：A 的骨架，借一点 B 的温度。

默认保留冷白与蓝色，页标题使用克制的衬线；任务列表维持清晰的无衬线。先解决手机表单、日期语义和重复来源，再考虑把 C 的密度做成选项。这样既能看出提升，也不会改变已熟悉的操作路径。
