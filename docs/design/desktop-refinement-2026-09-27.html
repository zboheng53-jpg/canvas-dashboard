推荐实施的四处微调

先完成这四处，就足够形成一轮可感知的改善。

A / 上方降权

缩短卡片，而非拆掉卡片

上一稿“全部压成一条”的幅度偏大。这次保留天气、日期、教学周的三个区域，也保留三个统计卡。

  • 环境卡由约 124 px 收至 84–88 px；时钟 34 → 20 px，默认显示到分钟。湿度放入可点击、可键盘打开的天气详情。
  • 统计卡由约 113 px 收至 72–76 px；数字 26 → 22 px，标签与数字同一行。
  • 删除“待完成 4 / 4 项待处理”的同义重复；保留下一节课、实际逾期数量等有用补充。
  • 不改指标口径；去掉环境卡整体 hover 提亮，只让真正可操作的控件响应。
目标：上方释放约 75–85 px，让首屏更早出现任务。实际高度以字体回退、窄桌面和缩放验收为准。
B / 行内去重

一行只回答一次“从哪里来”

左侧保持“标题 + 辅助信息”，右侧保持“时间 + 操作”，只重整每个位置的内容。

  • 辅助行保留既有彩色分类标签，例如紫色“项目”、灰色“自定义”及各平台来源色，再接课程或项目名称。保留用户标签、分类筛选与项目名称的跳转能力。
  • 移除右侧重复来源；保留“已断开”、用户标签和有区别的事项类型。
  • 日期明确为“截止 9/29 23:59”“计划 今天”“未设截止”；全天截止不凭空补 23:59。
  • 同时有计划与截止时，右侧优先截止，计划留辅助行；跨年显示年份。原始日期值与编辑方式保持。
对齐：标题与右侧日期共享第一行文字基线；同类日期右边缘一致。较长标题自然增高，操作不挤进文字中。
C / 字号与颜色

把任务读清楚，靠层级而非浓底色

任务已经是无衬线，无需换字体。建议只调整列表及右栏辅助文字的几个语义用色。

  • 任务标题 13.5 → 15 px，字重约 600、行高 22 px；辅助文字 12.5 px / 18 px；日期 12.5 px。
  • 保留页面／分区的衬线标题；行内任务、按钮与时间使用现有无衬线。
  • 课程／时间等辅助文字由 muted 改用现有 secondary；彩色分类标签沿用既有颜色：蓝白 #5b6472、苔绿 #606b59。分别对卡片底色约 5.98:1、5.55:1。
  • 逾期使用窄红线 + “逾期”文字；普通任务保持白底。计划日期不因计划已过而染红。
颜色改在具体文字角色上，避免全局加深 muted 导致其他模块一起变重。红色小字同样须核查对比度。
D / 操作与动效

可点击的反馈一致，位置稳定

无需把完成按钮整体搬到最左侧。在现有右侧操作区，让高频动作更容易找到即可。

  • “完成”排在操作区第一位并常显；标记与删除保留较轻的视觉，hover／focus 时强调。
  • 图标视觉约 14–16 px，桌面点击区目标 28–32 px；统一尺寸与基线，不因 hover 改布局。
  • 边框、背景的反馈复用现有 120–160 ms；保留 280 ms 渐入和减少动态效果设置。
  • 新增／保存失败保留输入；刷新不夺取输入焦点，不把列表滚回顶部。此处做回归确认。
“完成后撤销”单独作为可选小交互，先核验各来源恢复能力与失败处理；不把永久删除当成可撤销。

“共同设计规则”如何用到这一轮

把通用原则收敛成桌面端的具体检查。

文字与间距

本轮调整仅提升任务字号和辅助行可读性。卡片圆角继续沿用，列表内边距优先统一至横向 18 px、纵向约 12 px，常见两行任务约 66–70 px。

验收标题、来源、时间不互相挤压；长标题可换行，行高自然增长。系统字体回退和 200% 缩放后，内容与操作仍可达。

颜色与紧急程度

本轮调整品牌色用于选中、主操作和计划信息；按用户确认保留彩色分类标签的名称、底色与边框，不降为纯文字或小圆点。逾期由明确文字和小面积红色表达。

验收普通有效文字目标至少 4.5:1。当前 muted 在两套卡片底色上分别约 3.68:1、4.27:1；将需要阅读的文字改为 secondary。W3C 对比度依据

触控与键盘

本轮调整桌面操作固定占位，键盘 focus 与 hover 同等清楚。天气详情等低频信息不能只藏在鼠标悬停里。

验收Tab 可达，焦点不被裁剪。桌面按钮 28–32 px 是本方案目标；WCAG 2.2 AA 基线为 24 × 24 CSS px，另有间距等例外。W3C 目标尺寸依据

窄屏与长内容

本轮调整在桌面内容列变窄时允许标题换行，让日期与操作保有固定空间；必要时行内换行，不改变整体三栏职责。

验收1280 / 1440 / 1920 px、侧栏展开／收起与 960／961 px 边界；normal / dense / empty。复查 768／769 px，避免桌面规则覆盖手机。

反馈与状态

本轮处理已有渐入、焦点与草稿保护沿用并验证。同步正常文字保持轻量；失败明确指出平台与影响，不用“加载中”覆盖最后可用数据。

后续可选完成后的可撤销反馈属于交互变更，另行验证多来源恢复和错误分支。本轮视觉示意没有实现此行为。

实施边界与验收

推荐 A + B + C + D；想更保守，可以先只做 B + C。

代码落点保持局部

  1. index.html：来源合并、日期显示文案、统计副文案与操作顺序。保留事件绑定、原始日期值和事项来源语义。
  2. 现有 CSS 责任层：局部调整桌面环境卡、统计卡、待办行；字号、语义色与动效复用 tokens。修改命中的既有规则，避免再叠一层全局覆盖。
  3. 设计契约：将任务／辅助文字的具体规则写回 DESIGN_SYSTEM.md；不扩大成组件体系重构。

本轮交付是可评审的方案文件；产品代码、API、数据口径与线上部署没有随此文件改变。

一轮验收看五件事

  1. 首屏更早看见待办；顶部依然能快速读到天气、日期和教学周。
  2. 每条任务只有一处来源；计划／截止／未设截止一眼分清。
  3. 蓝白与苔绿都以白色卡片为主；辅助文字清楚，逾期小字不刺眼也不太淡。
  4. 长标题、无日期、计划与截止同时存在、来源断开、子任务展开均不重叠。
  5. 键盘操作、内联改期、刷新时输入、减少动态效果和手机断点保持可用。
